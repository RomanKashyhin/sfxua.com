# LayerLab — инструмент для настройки звука под видео

Рабочее название: **LayerLab** (поменяем, если не нравится).
Ветка: `tool/layerlab-ui`. Папка: `layerlab/` (в `_dev/` нельзя: она исключена из git).

## 1. Что это

Приложение на компьютер. Посередине — видео. По бокам — панели.
В панелях — ползунки, которые меняют **характер** звука прямо во время
проигрывания видео: двинул «Сила ветра» — ветер в эмбиенте стал сильнее,
двинул «Листва» — зашуршало больше листвы. Звук слушаешь сразу под картинкой.

Звук не один файл, а **лейеринг**: набор слоёв (ветер-низ, ветер-верх, порывы,
пыль, листва…). Ползунок — это не громкость одного слоя, а **макро**: одна ручка
тянет сразу несколько параметров нескольких слоёв (громкость, фильтр, скорость,
плотность, разброс питча).

Разбивку на слои делаешь ты. Я делаю инструмент, в который слои кладутся.

## 2. Из чего состоит

### 2.1. Экран

```
┌───────────────┬────────────────────────────┬───────────────┐
│ СЛОИ          │                            │ ПОЛЗУНКИ      │
│               │                            │               │
│ [Эмбиент]     │         ВИДЕО              │ Сила ветра ─●─│
│ [Шаги]        │                            │ Пыль       ──●│
│ [Удары]       │                            │ Листва     ●──│
│               │                            │ Даль/близь ─●─│
│ ветер-низ  ▮▮ │                            │               │
│ ветер-верх ▮  │  ▶ ⏸  00:12.40 / 01:30.00  │ [A] [B] сброс │
│ порывы     ▮▮▮│  ━━━━━━●━━━━━━━━━━━━━━━━━  │ пресеты ▾     │
│ пыль       ▮  │  [loop ◁ ▷]                │               │
│ + слой        │                            │ мастер ───●─  │
└───────────────┴────────────────────────────┴───────────────┘
```

- **Центр** — видео, play/pause, таймкод, скраб, A-B луп (крутить один кусок
  сцены по кругу, пока настраиваешь).
- **Слева** — наборы слоёв (вкладки: Эмбиент, Шаги, Удары…) и сами слои
  выбранного набора: имя, индикатор уровня, mute/solo, своя громкость.
- **Справа** — макро-ползунки выбранного набора. Для эмбиента свои, для шагов
  свои. Кнопки A/B (сравнить две настройки), сброс, пресеты.
- **Низ** (позже) — таймлайн с маркерами: где шаг, где удар, автоматизация
  ползунков по времени.

### 2.2. Два типа слоёв

| Тип | Пример | Как играет |
|---|---|---|
| **Петля (loop)** | ветер, пыль, гул, листва | крутится постоянно, макросы меняют громкость/фильтр/скорость |
| **Ван-шот (one-shot)** | шаг, удар, хруст | запускается по событию: клик, клавиша, маркер на таймлайне; из пула вариантов (round-robin), случайный питч/громкость |

### 2.3. Макро-ползунок = карта влияния

Один ползунок описывается так: имя, диапазон, значение по умолчанию и список
«что он тянет». Пример для «Сила ветра» (0…100):

| Слой | Параметр | 0 → 100 |
|---|---|---|
| ветер-низ | громкость | −12 dB → 0 dB |
| ветер-верх | громкость | −30 dB → −6 dB |
| ветер-верх | фильтр (срез) | 800 Hz → 6 kHz |
| порывы | плотность | 0 → 8 в минуту |
| листва | громкость | +0 → +4 dB (ветер шевелит листву) |

Такие карты задаются в JSON (или в UI через «привязать»). Карта с `"mode": "mul"`
не задаёт параметр, а домножает его относительно своего `from` — так «Даль / близко»
приглушает верха поверх того, что выставила «Сила ветра». У слоя есть `trim` (дБ):
подъём тихого файла до рабочего уровня, чтобы карты считались от нормального нуля. Это и есть
«характер» — он сидит в картах, а не в кнопке «громче».

### 2.4. Файл проекта

Один JSON рядом с видео и звуками:

```json
{
  "video": "scene01.mp4",
  "sets": [
    {
      "name": "Эмбиент",
      "layers": [
        { "id": "wind_low",  "file": "amb/wind_low.wav",  "mode": "loop" },
        { "id": "wind_high", "file": "amb/wind_high.wav", "mode": "loop" },
        { "id": "gusts",     "file": "amb/gust_*.wav",    "mode": "oneshot", "density": 4 },
        { "id": "leaves",    "file": "amb/leaves.wav",    "mode": "loop" }
      ],
      "macros": [
        { "id": "wind", "name": "Сила ветра", "default": 40,
          "map": [
            { "layer": "wind_low",  "param": "gain",   "from": -12, "to": 0 },
            { "layer": "wind_high", "param": "gain",   "from": -30, "to": -6 },
            { "layer": "wind_high", "param": "cutoff", "from": 800, "to": 6000 },
            { "layer": "gusts",     "param": "density","from": 0,   "to": 8 }
          ] }
      ]
    }
  ],
  "snapshots": { "A": { "wind": 40, "dust": 20 }, "B": { "wind": 75, "dust": 60 } }
}
```

## 3. На чём делать

**Рекомендация: веб-технологии (HTML + Web Audio API), обёрнутые в Electron.**

Почему:
- Видео — родной `<video>`, звук — Web Audio: граф узлов (источник → громкость
  → фильтр → панорама → шина → мастер) меняется в реальном времени без щелчков.
- UI (ползунки, панели) делается быстро и выглядит как мы захотим.
- **Первые этапы вообще без Electron** — просто страница в браузере. Я могу
  показывать её тебе в превью прямо из этой сессии, ты — открыть с телефона
  или второго компа по локальной сети. Electron добавляем, когда нужны
  папки на диске, drag-and-drop проектов и установка как «приложение».
- Сохранение/экспорт: `OfflineAudioContext` отрендерит микс в WAV без
  реального времени.

Альтернативы и почему нет:
- **Unity** — ты в нём живёшь, но видеоплеер + кастомный UI там тяжелее и
  медленнее итерируется. Зато потом карты макросов можно экспортировать в
  параметры твоей SFX Audio System / FMOD — это стоит заложить в формат JSON.
- **JUCE (C++)** — профессионально, но каждая правка UI — компиляция. Для
  инструмента «под себя» избыточно.
- **Python + Qt** — звук в реальном времени с низкой задержкой там больнее.

## 5. Что нужно от тебя

1. Примеры ползунков (скрины/референсы), о которых ты говорил.
2. Первый набор звуков: эмбиент или шаги. Уже разбитый на слои, с именами
   файлов, какой слой — петля, какой — ван-шот.
3. Для каждого ползунка — одна фраза: «что он должен делать с какими слоями».
   Таблицу влияния из 2.3 заполню я, ты потом подправишь на слух.

## 6. Удобства, которые закладываю сразу

- Колесо мыши над ползунком — точная подстройка; двойной клик — в дефолт.
- Горячие клавиши: пробел — play/pause, `[` `]` — границы лупа, `A`/`B` —
  снимки, цифры 1–9 — триггер ван-шотов.
- Ползунки крупные, чтобы можно было крутить и с тачскрина/телефона.
- Всё состояние в одном JSON — легко слать мне в чат, легко версионировать.

## 7. Риски

- Браузер не даёт звук до первого клика — первый play по кнопке, не авто.
- Синхронизация звука с видео: звук ведём от `video.currentTime`, при
  расхождении > 40 мс мягко подтягиваем.
- Длинные wav — память: декодируем один раз, храним в буферах.

# Часть 2. Модуль шагов (01.11.2026)

## 8. Что разобрано

### 8.1. BOOM Library — Virtual Foley Artist: Footsteps (стоит на D:)

Это инструмент для Kontakt 5 (2015, v1.1 2016) плюс 43 готовых wav. На диске:
`PART 1/Virtual Foley Artist - Footsteps/Samples/` — 30 736 wav, 46 папок, мануал в PDF.

**Как устроен шаг.** Шаг = **Heel** (пятка) → **Tip** (носок) → **Rel** (отрыв, release:
звук, когда нога уходит с поверхности; его громкость и есть «шарканье» — ручка
Release Volume −40…+40 dB, по умолчанию −10). Отдельно: **Slides** трёх длин
(Short / Normal / Long), **Stairs** (одним файлом, Full), и на клавишах G#–B
особые звуки поверхности (скрип досок, дребезг металла).

**Как лежат файлы.** Папка = `<Обувь> 01 <Поверхность> 01 Dry`, внутри `Left`, `Right`,
`Slides`, `Stairs`. Имя файла = `<код> - <зона силы> - <артикуляция> <номер>.wav`:
`BO01 CC01D L - 60-109 - Heel 07.wav`. Зоны силы по velocity: `01-59` (мягко),
`60-109` (средне), `110-127` (жёстко); в каждой 15–30 вариантов (round-robin).

| Что | Варианты |
|---|---|
| Обувь (5) | Boots, Dress Boots, High Heels, Leather Shoes, Sneaker |
| Поверхность (8, записана под каждую обувь) | Concrete Clean, Concrete Gritty, Gravel Light, Gravel Medium, Metal, Sand, Wood Parquet, Wood Plank |
| Обобщённые поверхности (одни на всех) | Leaves, Snow (с подпапками Left/Right), Water |
| Аксессуары (`Additional Layers`) | Cloth (штанина), Leather 1–3, Metal 1–2 — свои Heel/Tip/Rel |
| Доп. звуки поверхности | `Metal Additional` RA1/RA2/RO1/RO2 (дребезг/гул), `Wood Planks Additional` C1/C2/S1/S2 (скрип/стук) |

У каблуков нет Rel (нечему шаркать). Snow и Leaves хранят Rel в зонах 125/126/127.

**Управление в плагине.** Главная страница: Shoes (основная + вторая обувь на подмес,
у каждой Volume/Tune/Mute/Solo), Accessories (до двух, те же ручки), Surfaces (4 под
обувь + 1 общая), **Distance** колесом pitch-bend (вниз ближе, вверх дальше).
Режим SINGLE (одна клавиша = пятка + носок через **Tip Delay**, 75 мс) или SPLIT
(играешь пятку и носок сам). Settings: EQ 3 полосы, компрессор, реверб (включён,
«скорее воздух, чем комната»), **Pitch Random** (± центы), **Transient Random**
(минус только смягчает атаку), **Release Volume**. Сила удара — velocity клавиши.
Раскладка: C пятка Л, C# носок Л, D пятка П, D# носок П, E лестница, F/F#/G
скольжения, G#–B спецзвуки.

### 8.2. UVI Walker / Walker 2 (есть `Walker 2.ufs` на D:)

Walker (2018) и Walker 2 (2022, новый движок). Сэмплы зашиты в .ufs, по файлам не
посмотреть, разбор по мануалу Walker 2 и статьям UVI.

**Слои.** Три полосы, у каждой свой канал: **Shoes & Feet** (+ подслой: пряжки,
шнурки, скрип, шпоры, вода), **Clothing** (24 вида одежды + подслой «что надето»:
рюкзак, цепи, ключи, кольчуга), **Surface** (до 32 поверхностей, включая лестницы
вверх/вниз, + подслой). Шаг = Heel → Toe, во второй версии плюс **Lift** (отрыв,
записан отдельно) и отдельные наборы для медленных / обычных / быстрых шагов.
4 микрофонных профиля, Distance = кроссфейд ближнего и дальнего микрофона.

**Ручки.** На каждую полосу: Power, Solo, Volume, Pitch, **Random** (разброс питча),
Attack, Decay. Блок Steps: **Speed** (пауза пятка→носок), **Auto** (пауза сама
подстраивается под темп игры), **Distance** (на mod wheel), Reverb Send и **Link**
(реверб идёт вместе с дистанцией), **Velocity** (чувствительность), **Lift**
(уровень отрыва). В первой версии: **Sens** (та же пауза), **Dyn Range** + Pitch
(«влево и питч вверх — тощий персонаж, влево и питч вниз — тяжёлый»),
**Auto-Scuff** (сам подмешивает шарканье), Stairs (меняет порядок: носок раньше
пятки). FX: EQ, компрессор, свёрточный реверб (46 импульсов по размеру комнаты),
лимитер.

**Пресеты** = персонаж × место: «Heavyset | Street», «Knight | Stoned Room»,
«High Heels | Train Station». Отдельный банк «Spaces» только с поверхностями.
Триггер только MIDI: C2 шаг левой, E2 правой, D2 Stop, F2 Scuff; автохода нет
ни в одном из двух.

### 8.3. Что берём себе

| Идея | Откуда | У нас |
|---|---|---|
| Шаг = пятка → носок → отрыв, пауза между ними — ручка | оба | «Темп»: шагов/мин, пятка→носок, носок→отрыв |
| Отрыв как отдельный слой, громкость = «шаркает ↔ чётко» | BOOM Release Volume, Walker Lift | «Шарканье»: отрыв, вероятность скольжения, длина |
| Случайный питч/громкость/время на каждый удар, round-robin без повторов | оба | «Разброс»: питч (центы), громкость (дБ), время (мс) |
| Дистанция одной ручкой: громкость + срез верхов (+ реверб позже) | pitch-bend / mod wheel | «Даль / близко» с подползунками |
| Вес как сочетание: зона силы + низ + баланс пятки и носка | Walker Dyn Range + Pitch, BOOM velocity | «Вес»: пятка (зона + громкость), носок, низ |
| Аксессуары тихо подмешиваются, до двух | BOOM | «Фурнитура»: аксессуар 1, 2, доп. поверхность |
| Пресет = персонаж × место | Walker | «Характеры», которые выбираю я |
| Стрип на слой: громкость / mute / solo / метр | оба | слои слева |

Чего в тех двух нет, а у нас уже есть: **автоход** (кнопка «Идти», шаги сами
чередуются Л/П в темпе, пока идёт видео), запуск клавишами без MIDI, видео рядом.

## 9. Как устроен наш модуль шагов

**Компоненты шага** (слои слева, у каждого громкость, M/S, метр): пятка, носок,
отрыв, скольжение, лестница, доп. поверхность, аксессуар 1, аксессуар 2.
Выбор обуви / поверхности / доп. поверхности / двух аксессуаров — списками,
сразу из индекса библиотеки (`layerlab/vfa-index.json`, строится скриптом
`layerlab/tools/index_vfa.py`; сами wav отдаёт `layerlab/serve.py` с D:).

**Макро → три подползунка** (главный тянет все три на одну величину, стрелка ▸
раскрывает их, каждый можно сдвинуть отдельно):

| Главный | Подползунки | Что меняют |
|---|---|---|
| Вес | Пятка · Носок · Низ | зона силы (мягко/средне/жёстко) и громкость пятки; громкость носка; low-shelf 160 Гц |
| Темп | Шагов/мин · Пятка→носок · Носок→отрыв | темп автохода 50–180; паузы 220→40 мс и 260→60 мс |
| Шарканье | Отрыв · Скольжения · Длина | громкость отрыва −24…+6; вероятность скольжения 0–80 %; короткое/среднее/длинное |
| Фурнитура | Аксессуар 1 · Аксессуар 2 · Доп. поверхность | громкости −24…+6 |
| Разброс | Питч · Громкость · Время | ±0–120 центов, ±0–6 дБ, ±0–40 мс на каждый удар |
| Даль / близко | Громкость · Верха · Низ | 0…−18 дБ; срез 16 кГц→1.5 кГц; обрез низа 40→300 Гц |

**Запуск:** кнопки и клавиши `1` шаг левой, `2` правой, `3` скольжение,
`4` лестница, `G` идти/стоп. Автоход живёт только пока идёт видео (или если видео
не открыто). Один шаг = пятка, через паузу носок, через паузу отрыв; аксессуары и
доп. поверхность бьют свои пятку/носок/отрыв в те же моменты (+4 мс);
скольжение с заданной вероятностью после носка.

**Характеры** (стартовые точки, доводить на слух): тяжёлые ботинки по бетону
жёстко · крадётся в кроссовках по паркету · каблуки по паркету резко · деловой
шаг в кожаных туфлях · сапоги по гравию медленно · по листве в лесу · шаги
вдалеке по металлу. Характер = выбор обуви/поверхности/слоёв + положение всех
ползунков и подползунков. Лежат в `steps.js` (CHARACTERS).

**Граф звука.** голос (BufferSource, случайный playbackRate и gain) → компонент
(макро-громкость → пользовательская громкость/M/S → анализатор) → шина шагов
(low-shelf → highpass → lowpass → громкость дистанции) → мастер.

## 10. Что дальше по шагам

1. Послушать характеры, поправить карты (диапазоны в `steps.js`).
2. Маркеры на таймлайне: шаг на кадре, автоход по размеченным точкам, экспорт.
3. Режим SPLIT (пятка и носок на разных клавишах) и «лестница» с обратным порядком.
4. Transient Random (как в BOOM), реверб/комната на «Даль / близко».
5. Вторая обувь на подмес (BOOM) и слой одежды (Walker) как ещё два компонента.
6. Время загрузки: сейчас 360 файлов ≈ 30 с с диска D:; кэш в памяти между
   переключениями, подгрузка по приоритету, меньше вариантов на зону при старте.

# Часть 3. Как сделать из этого современную тулзу (предложение, 01.11.2026)

## 11. Сценарий, под который всё затачиваем

1. Открыл видео из игры, персонаж бежит.
2. За минуту подобрал характер шагов: ткнул в картинку обуви и поверхности,
   покрутил Вес и Темп, послушал под картинку.
3. Нажал «Выгнать» — получил WAV-файлы слоями, ровно столько, сколько нужно
   игре (3 файла, а не 15), плюс JSON-рецепт, чтобы потом вернуться и поправить.

Всё остальное ниже служит этим трём шагам.

## 12. Что видно в Walker 2 и что берём

Как он устроен визуально (см. картинки на uvi.net/walker-2):

- **Три круга** — большой с фотографией обуви, под ним два поменьше:
  поверхность и одежда, соединены линиями. Сразу видно, из чего собран шаг,
  и что в нём главное.
- **Полоса на каждый слой** справа: кнопка питания, название, крутилки
  Volume · Pitch · Random · Attack · Decay, слот «Empty» для подслоя
  (пряжки, шнурки, рюкзак). Полосы раскрашены: обувь тёмная, поверхность
  зелёная, одежда фиолетовая.
- **Слева крупные крутилки** того, что крутят чаще всего: Speed (+ Auto),
  Distance (+ Link к ребербу), Reverb; мелкие Velocity и Lift.
- **Выбор звука — галерея картинок**: гравий, снег, плитка, кроссовки,
  лапы, пальто. Не списки, а фотографии.
- Сверху профили микрофона и страница FX.

Берём: круги-слои с линиями, полосу с крутилками на каждый слой, крупные
крутилки для главного, галерею картинок вместо выпадающих списков, цвет на
тип слоя. Не берём: один шаг = один сэмпл без разбора на пятку и носок
(у нас глубже), MIDI как единственный запуск, отсутствие экспорта слоями.

### 13.1. Крутилки вместо ползунков там, где это компактнее

- **Вес** и **Темп** — две большие крутилки рядом, под каждой ряд маленьких:
  у Веса — Пятка · Носок · Низ · **Питч**; у Темпа — Шагов/мин · Пятка→носок ·
  Носок→отрыв. Большая крутилка двигает маленькие, маленькие можно крутить
  отдельно (та же логика, что у подползунков сейчас).
- Крутилка: тянуть вверх/вниз, колесо — точно, двойной клик — в дефолт,
  Shift — медленно. Значение подписано под ней.
- Шарканье, Фурнитура, Разброс, Даль остаются ползунками: их крутят реже
  и они длинные по смыслу («от и до»).

### 13.2. Вес — что он на самом деле делает

Сейчас Вес = зона силы + громкость пятки/носка + низ. Предлагаю:

| Подкрутилка | Что делает | Диапазон |
|---|---|---|
| Пятка | зона силы (мягко/средне/жёстко) и громкость пятки | зона 0→1, −10…+4 дБ |
| Носок | громкость носка | −12…+6 дБ |
| Низ | low-shelf 160 Гц | −6…+9 дБ |
| **Питч** | тон всего шага: тяжёлый — ниже, лёгкий — выше | +3…−4 полутона |
| (скрытое) | атака: тяжёлый шаг с более тупой атакой | fade-in 0…8 мс |

Так «вес 22» = лёгкая зона, тихая пятка, срезанный низ, питч +1.5 st, острая
атака; «вес 85» = жёсткая зона, пятка вперёд, низ +7, питч −3 st. И каждый
кусок крутится отдельно.

### 13.3. Полоса на каждый слой (как в Walker)

У каждого компонента (пятка, носок, отрыв, скольжение, ткань, аксессуары,
поверхность): **вкл · M · S · Vol · Pitch (st + fine) · Random · Attack ·
Decay/длина · Low cut · High cut · Pan · Offset (мс)**. Offset — это сдвиг
по времени относительно пятки, он же рисуется в «анатомии шага».

### 13.4. Анатомия шага — главное новое окно

Горизонтальная шкала 0…600 мс, на ней дорожки компонентов с волнами
реальных сэмплов (последнего сыгранного шага). Видно наслоение: где пятка,
где носок, где отрыв, где ткань. Блок можно тянуть по времени (Offset), клик
по дорожке — соло, колесо — громкость. Каждый новый шаг перерисовывает волны:
слышишь и видишь одно и то же.

### 13.5. Выбор через картинки

Галерея плиток: обувь (5 фото), поверхности (8 + 3 общие), аксессуары.
Плитка с подсветкой выбранной, под ней маленький «+» для второй обуви и
аксессуаров. Фото делаем из библиотек или генерируем одним стилем.

## 14. Экспорт слоями — ключевая функция

**Группы на выгрузку** настраиваются: по умолчанию три —
`шаг` (пятка + носок + отрыв), `ткань` (аксессуары), `поверхность`
(доп. поверхность + скольжение). Можно любую другую разбивку: «пятка отдельно,
носок отдельно, всё остальное вместе» — перетаскиванием компонентов в группы.

Что получается на диске:

```
Steps_Boots_ConcreteGritty_Heavy/
  step_01.wav … step_06.wav        ← 6 вариантов, каждый = свой round-robin + свой случайный питч
  cloth_01.wav … cloth_06.wav
  surface_01.wav … surface_06.wav
  mix_01.wav … mix_06.wav          ← по желанию, всё вместе
  recipe.json                      ← характер, все крутилки, какие сэмплы попали в какой вариант
```

Как рендерим: `OfflineAudioContext`, тот же граф, что играет вживую (фильтры,
громкости, питч, случайности) — только без мастера и дистанции (или с ними,
галочка). Нормализация: пик −1 dBFS или заданный LUFS, 48 кГц / 24 бит, имя
по шаблону (UCS-подобное: `FOOTBoot_Concrete Gritty Heavy_01.wav`).
Варианты должны отличаться: round-robin без повторов, фиксированное зерно
случайности в рецепте, чтобы выгрузка была воспроизводимой.

Для Unity: вместе с WAV класть YAML/JSON под твою SFX Audio System — набор
клипов + параметры (громкость, разброс питча), чтобы импорт был одной кнопкой.

## 15. Современные подходы, которые стоит заложить

1. **Шаги из видео автоматически.** Поза персонажа в кадре через MediaPipe
   Pose / RTMPose в браузере (ONNX) → моменты касания стопы → маркеры шагов на
   таймлайне, темп и даже вес (по амплитуде движения). Ты смотришь ролик, а шаги
   уже стоят на кадрах; остаётся подобрать характер. Для игрового видео это
   работает, когда персонаж в кадре целиком; для мелкого плана — tap-tempo.
2. **Tap-tempo и маркеры руками.** Жмёшь клавишу в такт шагам на видео,
   тулза ставит маркеры и вычисляет темп; потом «Идти по маркерам» и экспорт
   стема под ролик.
3. **Поиск по похожести (CLAP-эмбеддинги).** Перетащил референс-шаг из
   чужой игры → тулза находит ближайшую обувь/поверхность в библиотеке и
   выставляет Вес/Шарканье. Модель CLAP крутится локально (Python), индексация
   библиотеки один раз.
4. **Генерация недостающего слоя по описанию.** Нет снега под каблуки —
   «хруст снега, мягкий, близко» → слой из генеративной модели (ElevenLabs SFX,
   Stable Audio), сразу в компонент «доп. поверхность». С пометкой, что это
   синтетика.
5. **XY-пад морфинга между четырьмя характерами.** В углах «тяжёлый»,
   «крадётся», «бежит», «далеко»; палец на планшете — все крутилки
   интерполируются. Удобно именно под видео.
6. **Планшет как пульт.** Та же страница по локальной сети на планшете:
   крутилки под пальцем, видео на мониторе; состояние синхронно через WebSocket.
   Плюс Web MIDI для контроллера.
7. **Автоматизация крутилок по таймлайну.** Персонаж перешёл с бетона на
   гравий — на таймлайне кривая «поверхность», кроссфейд слоёв; Вес растёт,
   когда он устал. Это уже уровень DAW, но нужно для стемов под ролик.
8. **Экспорт в игровые контейнеры.** Карты влияния = RTPC: Вес → параметр
   Weight в Wwise/FMOD/твоей системе. Тулза выгружает не только WAV, но и
   «как их смешивать»: blend-контейнер с кривыми.
9. **Loudness и контроль.** LUFS/true-peak на мастере и при экспорте,
   индикатор клиппинга, нормализация групп к одному уровню.
10. **Лёгкая и быстрая загрузка.** Предслушивание на 3 вариантах на зону
    (секунды), остальное догружается фоном; кэш декодированных буферов в
    IndexedDB, чтобы второй раз открывалось мгновенно.

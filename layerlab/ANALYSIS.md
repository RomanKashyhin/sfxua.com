# LayerLab — инструмент для настройки звука под видео

Рабочее название: **LayerLab** (поменяем, если не нравится).
Ветка: `tool/layerlab-ui`. Папка: `layerlab/` (в `_dev/` нельзя: она исключена из git).

## 1. Что это

Приложение на компьютер. Посередине — видео. По бокам — панели.
В панелях — ползунки, которые меняют **характер** звука прямо во время
проигрывания видео: двинул «Сила ветра» — ветер в эмбиенте стал сильнее,
двинул «Листва» — зашуршало больше листвы. Звук слушаешь сразу под картинкой.

Звук не один файл, а **лейеринг**: набор слоёв (ветер-низ, ветер-верх, порывы,
пыль, листва…). Ползунок — это не громкость одного слоя, а **макро**: одна ручка
тянет сразу несколько параметров нескольких слоёв (громкость, фильтр, скорость,
плотность, разброс питча).

Разбивку на слои делаешь ты. Я делаю инструмент, в который слои кладутся.

## 2. Из чего состоит

### 2.1. Экран

```
┌───────────────┬────────────────────────────┬───────────────┐
│ СЛОИ          │                            │ ПОЛЗУНКИ      │
│               │                            │               │
│ [Эмбиент]     │         ВИДЕО              │ Сила ветра ─●─│
│ [Шаги]        │                            │ Пыль       ──●│
│ [Удары]       │                            │ Листва     ●──│
│               │                            │ Даль/близь ─●─│
│ ветер-низ  ▮▮ │                            │               │
│ ветер-верх ▮  │  ▶ ⏸  00:12.40 / 01:30.00  │ [A] [B] сброс │
│ порывы     ▮▮▮│  ━━━━━━●━━━━━━━━━━━━━━━━━  │ пресеты ▾     │
│ пыль       ▮  │  [loop ◁ ▷]                │               │
│ + слой        │                            │ мастер ───●─  │
└───────────────┴────────────────────────────┴───────────────┘
```

- **Центр** — видео, play/pause, таймкод, скраб, A-B луп (крутить один кусок
  сцены по кругу, пока настраиваешь).
- **Слева** — наборы слоёв (вкладки: Эмбиент, Шаги, Удары…) и сами слои
  выбранного набора: имя, индикатор уровня, mute/solo, своя громкость.
- **Справа** — макро-ползунки выбранного набора. Для эмбиента свои, для шагов
  свои. Кнопки A/B (сравнить две настройки), сброс, пресеты.
- **Низ** (позже) — таймлайн с маркерами: где шаг, где удар, автоматизация
  ползунков по времени.

### 2.2. Два типа слоёв

| Тип | Пример | Как играет |
|---|---|---|
| **Петля (loop)** | ветер, пыль, гул, листва | крутится постоянно, макросы меняют громкость/фильтр/скорость |
| **Ван-шот (one-shot)** | шаг, удар, хруст | запускается по событию: клик, клавиша, маркер на таймлайне; из пула вариантов (round-robin), случайный питч/громкость |

### 2.3. Макро-ползунок = карта влияния

Один ползунок описывается так: имя, диапазон, значение по умолчанию и список
«что он тянет». Пример для «Сила ветра» (0…100):

| Слой | Параметр | 0 → 100 |
|---|---|---|
| ветер-низ | громкость | −12 dB → 0 dB |
| ветер-верх | громкость | −30 dB → −6 dB |
| ветер-верх | фильтр (срез) | 800 Hz → 6 kHz |
| порывы | плотность | 0 → 8 в минуту |
| листва | громкость | +0 → +4 dB (ветер шевелит листву) |

Такие карты задаются в JSON (или в UI через «привязать»). Карта с `"mode": "mul"`
не задаёт параметр, а домножает его относительно своего `from` — так «Даль / близко»
приглушает верха поверх того, что выставила «Сила ветра». У слоя есть `trim` (дБ):
подъём тихого файла до рабочего уровня, чтобы карты считались от нормального нуля. Это и есть
«характер» — он сидит в картах, а не в кнопке «громче».

### 2.4. Файл проекта

Один JSON рядом с видео и звуками:

```json
{
  "video": "scene01.mp4",
  "sets": [
    {
      "name": "Эмбиент",
      "layers": [
        { "id": "wind_low",  "file": "amb/wind_low.wav",  "mode": "loop" },
        { "id": "wind_high", "file": "amb/wind_high.wav", "mode": "loop" },
        { "id": "gusts",     "file": "amb/gust_*.wav",    "mode": "oneshot", "density": 4 },
        { "id": "leaves",    "file": "amb/leaves.wav",    "mode": "loop" }
      ],
      "macros": [
        { "id": "wind", "name": "Сила ветра", "default": 40,
          "map": [
            { "layer": "wind_low",  "param": "gain",   "from": -12, "to": 0 },
            { "layer": "wind_high", "param": "gain",   "from": -30, "to": -6 },
            { "layer": "wind_high", "param": "cutoff", "from": 800, "to": 6000 },
            { "layer": "gusts",     "param": "density","from": 0,   "to": 8 }
          ] }
      ]
    }
  ],
  "snapshots": { "A": { "wind": 40, "dust": 20 }, "B": { "wind": 75, "dust": 60 } }
}
```

## 3. На чём делать

**Рекомендация: веб-технологии (HTML + Web Audio API), обёрнутые в Electron.**

Почему:
- Видео — родной `<video>`, звук — Web Audio: граф узлов (источник → громкость
  → фильтр → панорама → шина → мастер) меняется в реальном времени без щелчков.
- UI (ползунки, панели) делается быстро и выглядит как мы захотим.
- **Первые этапы вообще без Electron** — просто страница в браузере. Я могу
  показывать её тебе в превью прямо из этой сессии, ты — открыть с телефона
  или второго компа по локальной сети. Electron добавляем, когда нужны
  папки на диске, drag-and-drop проектов и установка как «приложение».
- Сохранение/экспорт: `OfflineAudioContext` отрендерит микс в WAV без
  реального времени.

Альтернативы и почему нет:
- **Unity** — ты в нём живёшь, но видеоплеер + кастомный UI там тяжелее и
  медленнее итерируется. Зато потом карты макросов можно экспортировать в
  параметры твоей SFX Audio System / FMOD — это стоит заложить в формат JSON.
- **JUCE (C++)** — профессионально, но каждая правка UI — компиляция. Для
  инструмента «под себя» избыточно.
- **Python + Qt** — звук в реальном времени с низкой задержкой там больнее.

## 5. Что нужно от тебя

1. Примеры ползунков (скрины/референсы), о которых ты говорил.
2. Первый набор звуков: эмбиент или шаги. Уже разбитый на слои, с именами
   файлов, какой слой — петля, какой — ван-шот.
3. Для каждого ползунка — одна фраза: «что он должен делать с какими слоями».
   Таблицу влияния из 2.3 заполню я, ты потом подправишь на слух.

## 6. Удобства, которые закладываю сразу

- Колесо мыши над ползунком — точная подстройка; двойной клик — в дефолт.
- Горячие клавиши: пробел — play/pause, `[` `]` — границы лупа, `A`/`B` —
  снимки, цифры 1–9 — триггер ван-шотов.
- Ползунки крупные, чтобы можно было крутить и с тачскрина/телефона.
- Всё состояние в одном JSON — легко слать мне в чат, легко версионировать.

## 7. Риски

- Браузер не даёт звук до первого клика — первый play по кнопке, не авто.
- Синхронизация звука с видео: звук ведём от `video.currentTime`, при
  расхождении > 40 мс мягко подтягиваем.
- Длинные wav — память: декодируем один раз, храним в буферах.

# Часть 2. Модуль шагов (01.11.2026)

## 8. Что разобрано

### 8.1. BOOM Library — Virtual Foley Artist: Footsteps (стоит на D:)

Это инструмент для Kontakt 5 (2015, v1.1 2016) плюс 43 готовых wav. На диске:
`PART 1/Virtual Foley Artist - Footsteps/Samples/` — 30 736 wav, 46 папок, мануал в PDF.

**Как устроен шаг.** Шаг = **Heel** (пятка) → **Tip** (носок) → **Rel** (отрыв, release:
звук, когда нога уходит с поверхности; его громкость и есть «шарканье» — ручка
Release Volume −40…+40 dB, по умолчанию −10). Отдельно: **Slides** трёх длин
(Short / Normal / Long), **Stairs** (одним файлом, Full), и на клавишах G#–B
особые звуки поверхности (скрип досок, дребезг металла).

**Как лежат файлы.** Папка = `<Обувь> 01 <Поверхность> 01 Dry`, внутри `Left`, `Right`,
`Slides`, `Stairs`. Имя файла = `<код> - <зона силы> - <артикуляция> <номер>.wav`:
`BO01 CC01D L - 60-109 - Heel 07.wav`. Зоны силы по velocity: `01-59` (мягко),
`60-109` (средне), `110-127` (жёстко); в каждой 15–30 вариантов (round-robin).

| Что | Варианты |
|---|---|
| Обувь (5) | Boots, Dress Boots, High Heels, Leather Shoes, Sneaker |
| Поверхность (8, записана под каждую обувь) | Concrete Clean, Concrete Gritty, Gravel Light, Gravel Medium, Metal, Sand, Wood Parquet, Wood Plank |
| Обобщённые поверхности (одни на всех) | Leaves, Snow (с подпапками Left/Right), Water |
| Аксессуары (`Additional Layers`) | Cloth (штанина), Leather 1–3, Metal 1–2 — свои Heel/Tip/Rel |
| Доп. звуки поверхности | `Metal Additional` RA1/RA2/RO1/RO2 (дребезг/гул), `Wood Planks Additional` C1/C2/S1/S2 (скрип/стук) |

У каблуков нет Rel (нечему шаркать). Snow и Leaves хранят Rel в зонах 125/126/127.

**Управление в плагине.** Главная страница: Shoes (основная + вторая обувь на подмес,
у каждой Volume/Tune/Mute/Solo), Accessories (до двух, те же ручки), Surfaces (4 под
обувь + 1 общая), **Distance** колесом pitch-bend (вниз ближе, вверх дальше).
Режим SINGLE (одна клавиша = пятка + носок через **Tip Delay**, 75 мс) или SPLIT
(играешь пятку и носок сам). Settings: EQ 3 полосы, компрессор, реверб (включён,
«скорее воздух, чем комната»), **Pitch Random** (± центы), **Transient Random**
(минус только смягчает атаку), **Release Volume**. Сила удара — velocity клавиши.
Раскладка: C пятка Л, C# носок Л, D пятка П, D# носок П, E лестница, F/F#/G
скольжения, G#–B спецзвуки.

### 8.2. UVI Walker / Walker 2 (есть `Walker 2.ufs` на D:)

Walker (2018) и Walker 2 (2022, новый движок). Сэмплы зашиты в .ufs, по файлам не
посмотреть, разбор по мануалу Walker 2 и статьям UVI.

**Слои.** Три полосы, у каждой свой канал: **Shoes & Feet** (+ подслой: пряжки,
шнурки, скрип, шпоры, вода), **Clothing** (24 вида одежды + подслой «что надето»:
рюкзак, цепи, ключи, кольчуга), **Surface** (до 32 поверхностей, включая лестницы
вверх/вниз, + подслой). Шаг = Heel → Toe, во второй версии плюс **Lift** (отрыв,
записан отдельно) и отдельные наборы для медленных / обычных / быстрых шагов.
4 микрофонных профиля, Distance = кроссфейд ближнего и дальнего микрофона.

**Ручки.** На каждую полосу: Power, Solo, Volume, Pitch, **Random** (разброс питча),
Attack, Decay. Блок Steps: **Speed** (пауза пятка→носок), **Auto** (пауза сама
подстраивается под темп игры), **Distance** (на mod wheel), Reverb Send и **Link**
(реверб идёт вместе с дистанцией), **Velocity** (чувствительность), **Lift**
(уровень отрыва). В первой версии: **Sens** (та же пауза), **Dyn Range** + Pitch
(«влево и питч вверх — тощий персонаж, влево и питч вниз — тяжёлый»),
**Auto-Scuff** (сам подмешивает шарканье), Stairs (меняет порядок: носок раньше
пятки). FX: EQ, компрессор, свёрточный реверб (46 импульсов по размеру комнаты),
лимитер.

**Пресеты** = персонаж × место: «Heavyset | Street», «Knight | Stoned Room»,
«High Heels | Train Station». Отдельный банк «Spaces» только с поверхностями.
Триггер только MIDI: C2 шаг левой, E2 правой, D2 Stop, F2 Scuff; автохода нет
ни в одном из двух.

### 8.3. Что берём себе

| Идея | Откуда | У нас |
|---|---|---|
| Шаг = пятка → носок → отрыв, пауза между ними — ручка | оба | «Темп»: шагов/мин, пятка→носок, носок→отрыв |
| Отрыв как отдельный слой, громкость = «шаркает ↔ чётко» | BOOM Release Volume, Walker Lift | «Шарканье»: отрыв, вероятность скольжения, длина |
| Случайный питч/громкость/время на каждый удар, round-robin без повторов | оба | «Разброс»: питч (центы), громкость (дБ), время (мс) |
| Дистанция одной ручкой: громкость + срез верхов (+ реверб позже) | pitch-bend / mod wheel | «Даль / близко» с подползунками |
| Вес как сочетание: зона силы + низ + баланс пятки и носка | Walker Dyn Range + Pitch, BOOM velocity | «Вес»: пятка (зона + громкость), носок, низ |
| Аксессуары тихо подмешиваются, до двух | BOOM | «Фурнитура»: аксессуар 1, 2, доп. поверхность |
| Пресет = персонаж × место | Walker | «Характеры», которые выбираю я |
| Стрип на слой: громкость / mute / solo / метр | оба | слои слева |

Чего в тех двух нет, а у нас уже есть: **автоход** (кнопка «Идти», шаги сами
чередуются Л/П в темпе, пока идёт видео), запуск клавишами без MIDI, видео рядом.

## 9. Как устроен наш модуль шагов

**Компоненты шага** (слои слева, у каждого громкость, M/S, метр): пятка, носок,
отрыв, скольжение, лестница, доп. поверхность, аксессуар 1, аксессуар 2.
Выбор обуви / поверхности / доп. поверхности / двух аксессуаров — списками,
сразу из индекса библиотеки (`layerlab/vfa-index.json`, строится скриптом
`layerlab/tools/index_vfa.py`; сами wav отдаёт `layerlab/serve.py` с D:).

**Макро → три подползунка** (главный тянет все три на одну величину, стрелка ▸
раскрывает их, каждый можно сдвинуть отдельно):

| Главный | Подползунки | Что меняют |
|---|---|---|
| Вес | Пятка · Носок · Низ | зона силы (мягко/средне/жёстко) и громкость пятки; громкость носка; low-shelf 160 Гц |
| Темп | Шагов/мин · Пятка→носок · Носок→отрыв | темп автохода 50–180; паузы 220→40 мс и 260→60 мс |
| Шарканье | Отрыв · Скольжения · Длина | громкость отрыва −24…+6; вероятность скольжения 0–80 %; короткое/среднее/длинное |
| Фурнитура | Аксессуар 1 · Аксессуар 2 · Доп. поверхность | громкости −24…+6 |
| Разброс | Питч · Громкость · Время | ±0–120 центов, ±0–6 дБ, ±0–40 мс на каждый удар |
| Даль / близко | Громкость · Верха · Низ | 0…−18 дБ; срез 16 кГц→1.5 кГц; обрез низа 40→300 Гц |

**Запуск:** кнопки и клавиши `1` шаг левой, `2` правой, `3` скольжение,
`4` лестница, `G` идти/стоп. Автоход живёт только пока идёт видео (или если видео
не открыто). Один шаг = пятка, через паузу носок, через паузу отрыв; аксессуары и
доп. поверхность бьют свои пятку/носок/отрыв в те же моменты (+4 мс);
скольжение с заданной вероятностью после носка.

**Характеры** (стартовые точки, доводить на слух): тяжёлые ботинки по бетону
жёстко · крадётся в кроссовках по паркету · каблуки по паркету резко · деловой
шаг в кожаных туфлях · сапоги по гравию медленно · по листве в лесу · шаги
вдалеке по металлу. Характер = выбор обуви/поверхности/слоёв + положение всех
ползунков и подползунков. Лежат в `steps.js` (CHARACTERS).

**Граф звука.** голос (BufferSource, случайный playbackRate и gain) → компонент
(макро-громкость → пользовательская громкость/M/S → анализатор) → шина шагов
(low-shelf → highpass → lowpass → громкость дистанции) → мастер.

## 10. Что дальше по шагам

1. Послушать характеры, поправить карты (диапазоны в `steps.js`).
2. Маркеры на таймлайне: шаг на кадре, автоход по размеченным точкам, экспорт.
3. Режим SPLIT (пятка и носок на разных клавишах) и «лестница» с обратным порядком.
4. Transient Random (как в BOOM), реверб/комната на «Даль / близко».
5. Вторая обувь на подмес (BOOM) и слой одежды (Walker) как ещё два компонента.
6. Время загрузки: сейчас 360 файлов ≈ 30 с с диска D:; кэш в памяти между
   переключениями, подгрузка по приоритету, меньше вариантов на зону при старте.

# Часть 3. Как сделать из этого современную тулзу (предложение, 01.11.2026)

## 11. Сценарий, под который всё затачиваем

1. Открыл видео из игры, персонаж бежит.
2. За минуту подобрал характер шагов: ткнул в картинку обуви и поверхности,
   покрутил Вес и Темп, послушал под картинку.
3. Нажал «Выгнать» — получил WAV-файлы слоями, ровно столько, сколько нужно
   игре (3 файла, а не 15), плюс JSON-рецепт, чтобы потом вернуться и поправить.

Всё остальное ниже служит этим трём шагам.

## 12. Что видно в Walker 2 и что берём

Как он устроен визуально (см. картинки на uvi.net/walker-2):

- **Три круга** — большой с фотографией обуви, под ним два поменьше:
  поверхность и одежда, соединены линиями. Сразу видно, из чего собран шаг,
  и что в нём главное.
- **Полоса на каждый слой** справа: кнопка питания, название, крутилки
  Volume · Pitch · Random · Attack · Decay, слот «Empty» для подслоя
  (пряжки, шнурки, рюкзак). Полосы раскрашены: обувь тёмная, поверхность
  зелёная, одежда фиолетовая.
- **Слева крупные крутилки** того, что крутят чаще всего: Speed (+ Auto),
  Distance (+ Link к ребербу), Reverb; мелкие Velocity и Lift.
- **Выбор звука — галерея картинок**: гравий, снег, плитка, кроссовки,
  лапы, пальто. Не списки, а фотографии.
- Сверху профили микрофона и страница FX.

Берём: круги-слои с линиями, полосу с крутилками на каждый слой, крупные
крутилки для главного, галерею картинок вместо выпадающих списков, цвет на
тип слоя. Не берём: один шаг = один сэмпл без разбора на пятку и носок
(у нас глубже), MIDI как единственный запуск, отсутствие экспорта слоями.

### 13.1. Крутилки вместо ползунков там, где это компактнее

- **Вес** и **Темп** — две большие крутилки рядом, под каждой ряд маленьких:
  у Веса — Пятка · Носок · Низ · **Питч**; у Темпа — Шагов/мин · Пятка→носок ·
  Носок→отрыв. Большая крутилка двигает маленькие, маленькие можно крутить
  отдельно (та же логика, что у подползунков сейчас).
- Крутилка: тянуть вверх/вниз, колесо — точно, двойной клик — в дефолт,
  Shift — медленно. Значение подписано под ней.
- Шарканье, Фурнитура, Разброс, Даль остаются ползунками: их крутят реже
  и они длинные по смыслу («от и до»).

### 13.2. Вес — что он на самом деле делает

Сейчас Вес = зона силы + громкость пятки/носка + низ. Предлагаю:

| Подкрутилка | Что делает | Диапазон |
|---|---|---|
| Пятка | зона силы (мягко/средне/жёстко) и громкость пятки | зона 0→1, −10…+4 дБ |
| Носок | громкость носка | −12…+6 дБ |
| Низ | low-shelf 160 Гц | −6…+9 дБ |
| **Питч** | тон всего шага: тяжёлый — ниже, лёгкий — выше | +3…−4 полутона |
| (скрытое) | атака: тяжёлый шаг с более тупой атакой | fade-in 0…8 мс |

Так «вес 22» = лёгкая зона, тихая пятка, срезанный низ, питч +1.5 st, острая
атака; «вес 85» = жёсткая зона, пятка вперёд, низ +7, питч −3 st. И каждый
кусок крутится отдельно.

### 13.3. Полоса на каждый слой (как в Walker)

У каждого компонента (пятка, носок, отрыв, скольжение, ткань, аксессуары,
поверхность): **вкл · M · S · Vol · Pitch (st + fine) · Random · Attack ·
Decay/длина · Low cut · High cut · Pan · Offset (мс)**. Offset — это сдвиг
по времени относительно пятки, он же рисуется в «анатомии шага».

### 13.4. Анатомия шага — главное новое окно

Горизонтальная шкала 0…600 мс, на ней дорожки компонентов с волнами
реальных сэмплов (последнего сыгранного шага). Видно наслоение: где пятка,
где носок, где отрыв, где ткань. Блок можно тянуть по времени (Offset), клик
по дорожке — соло, колесо — громкость. Каждый новый шаг перерисовывает волны:
слышишь и видишь одно и то же.

### 13.5. Выбор через картинки

Галерея плиток: обувь (5 фото), поверхности (8 + 3 общие), аксессуары.
Плитка с подсветкой выбранной, под ней маленький «+» для второй обуви и
аксессуаров. Фото делаем из библиотек или генерируем одним стилем.

## 14. Экспорт слоями — ключевая функция

**Группы на выгрузку** настраиваются: по умолчанию три —
`шаг` (пятка + носок + отрыв), `ткань` (аксессуары), `поверхность`
(доп. поверхность + скольжение). Можно любую другую разбивку: «пятка отдельно,
носок отдельно, всё остальное вместе» — перетаскиванием компонентов в группы.

Что получается на диске:

```
Steps_Boots_ConcreteGritty_Heavy/
  step_01.wav … step_06.wav        ← 6 вариантов, каждый = свой round-robin + свой случайный питч
  cloth_01.wav … cloth_06.wav
  surface_01.wav … surface_06.wav
  mix_01.wav … mix_06.wav          ← по желанию, всё вместе
  recipe.json                      ← характер, все крутилки, какие сэмплы попали в какой вариант
```

Как рендерим: `OfflineAudioContext`, тот же граф, что играет вживую (фильтры,
громкости, питч, случайности) — только без мастера и дистанции (или с ними,
галочка). Нормализация: пик −1 dBFS или заданный LUFS, 48 кГц / 24 бит, имя
по шаблону (UCS-подобное: `FOOTBoot_Concrete Gritty Heavy_01.wav`).
Варианты должны отличаться: round-robin без повторов, фиксированное зерно
случайности в рецепте, чтобы выгрузка была воспроизводимой.

Для Unity: вместе с WAV класть YAML/JSON под твою SFX Audio System — набор
клипов + параметры (громкость, разброс питча), чтобы импорт был одной кнопкой.

## 15. Современные подходы, которые стоит заложить

1. **Шаги из видео автоматически.** Поза персонажа в кадре через MediaPipe
   Pose / RTMPose в браузере (ONNX) → моменты касания стопы → маркеры шагов на
   таймлайне, темп и даже вес (по амплитуде движения). Ты смотришь ролик, а шаги
   уже стоят на кадрах; остаётся подобрать характер. Для игрового видео это
   работает, когда персонаж в кадре целиком; для мелкого плана — tap-tempo.
2. **Tap-tempo и маркеры руками.** Жмёшь клавишу в такт шагам на видео,
   тулза ставит маркеры и вычисляет темп; потом «Идти по маркерам» и экспорт
   стема под ролик.
3. **Поиск по похожести (CLAP-эмбеддинги).** Перетащил референс-шаг из
   чужой игры → тулза находит ближайшую обувь/поверхность в библиотеке и
   выставляет Вес/Шарканье. Модель CLAP крутится локально (Python), индексация
   библиотеки один раз.
4. **Генерация недостающего слоя по описанию.** Нет снега под каблуки —
   «хруст снега, мягкий, близко» → слой из генеративной модели (ElevenLabs SFX,
   Stable Audio), сразу в компонент «доп. поверхность». С пометкой, что это
   синтетика.
5. **XY-пад морфинга между четырьмя характерами.** В углах «тяжёлый»,
   «крадётся», «бежит», «далеко»; палец на планшете — все крутилки
   интерполируются. Удобно именно под видео.
6. **Планшет как пульт.** Та же страница по локальной сети на планшете:
   крутилки под пальцем, видео на мониторе; состояние синхронно через WebSocket.
   Плюс Web MIDI для контроллера.
7. **Автоматизация крутилок по таймлайну.** Персонаж перешёл с бетона на
   гравий — на таймлайне кривая «поверхность», кроссфейд слоёв; Вес растёт,
   когда он устал. Это уже уровень DAW, но нужно для стемов под ролик.
8. **Экспорт в игровые контейнеры.** Карты влияния = RTPC: Вес → параметр
   Weight в Wwise/FMOD/твоей системе. Тулза выгружает не только WAV, но и
   «как их смешивать»: blend-контейнер с кривыми.
9. **Loudness и контроль.** LUFS/true-peak на мастере и при экспорте,
   индикатор клиппинга, нормализация групп к одному уровню.
10. **Лёгкая и быстрая загрузка.** Предслушивание на 3 вариантах на зону
    (секунды), остальное догружается фоном; кэш декодированных буферов в
    IndexedDB, чтобы второй раз открывалось мгновенно.

# Часть 4. Дистанция по физике: что говорит наука и как это сделано (01.11.2026)

Вопрос: как звук меняется по спектру с расстоянием — не реверберация, а именно
частоты. Ответ из акустики: три вещи, и все три считаются по формулам.

## 17. Что известно

### 17.1. Расхождение (громкость)

Точечный источник на открытом воздухе: уровень падает на **6 дБ на каждое
удвоение** расстояния (−20·log10(d/d₀)). Это не спектральный эффект, но без него
дистанция не работает, поэтому он в модели (отдельный GainNode, в FIR не входит).
Психоакустика: люди систематически **недооценивают** далёкие расстояния —
воспринимаемая дистанция ≈ k·dᵃ с показателем a < 1 (Zahorik, Brungart &
Bronkhorst 2005, обзор 84 наборов данных; в среднем a ≈ 0.5). Для игры это
значит: физический спад −6 дБ/удвоение звучит «честно», но персонаж в 100 м
будет казаться ближе, чем он есть.

### 17.2. Поглощение воздухом — ISO 9613-1:1993

Главный спектральный эффект дали. Коэффициент α(f) в дБ/м зависит от частоты,
температуры, влажности и давления; растёт примерно как f² на низких частотах и
«ломается» на частотах релаксации кислорода и азота (они зависят от влажности).
Формула стандарта (реализована в `distance.js → alphaAir`):

```
h   = RH · 10^( −6.8346·(273.16/T)^1.261 + 4.6151 )          % молярная доля воды
frO = 24 + 4.04·10⁴·h·(0.02+h)/(0.391+h)                     релаксация O₂, Гц
frN = (T/T₀)^−½ · (9 + 280·h·exp(−4.17·((T/T₀)^−⅓ − 1)))     релаксация N₂, Гц
α   = 8.686·f² · [ 1.84·10⁻¹¹·(T/T₀)^½
      + (T/T₀)^−5/2 · ( 0.01275·e^(−2239.1/T)/(frO + f²/frO)
                      + 0.1068·e^(−3352/T)/(frN + f²/frN) ) ]   дБ/м
```

Проверка нашей реализации против таблицы ISO 9613-2 (дБ/км, октавы 63…8000 Гц):

| Воздух | 63 | 125 | 250 | 500 | 1k | 2k | 4k | 8k |
|---|---|---|---|---|---|---|---|---|
| +20 °C, 70 % (ISO) | 0.1 | 0.3 | 1.1 | 2.8 | 5.0 | 9.0 | 22.9 | 76.6 |
| +20 °C, 70 % (наш код) | 0.1 | 0.3 | 1.1 | 2.8 | 5.0 | 9.0 | 23.1 | 77.6 |
| +10 °C, 70 % | 0.1 | 0.4 | 1.0 | 1.9 | 3.7 | 9.7 | 33 | 118 |
| +15 °C, 20 % (сухо) | 0.3 | 0.6 | 1.2 | 2.7 | 8.2 | 28 | 89 | 203 |
| −10 °C, 80 % (зима) | 0.1 | 0.3 | 0.7 | 2.2 | 7.8 | 25 | 61 | 99 |
| +35 °C, 20 % (жара) | 0.2 | 0.7 | 2.0 | 4.1 | 6.8 | 14 | 40 | 138 |

Что это значит на практике: на **100 м** летом верха теряют ≈ −2.3 дБ на 4 кГц и
−8…−10 дБ на 8 кГц, а ниже 1 кГц воздух почти ничего не делает. На 30 м — всего
−3 дБ на 8 кГц. То есть «даль = срез верхов» в чистом виде начинается с десятков
метров, и сухой/морозный воздух режет вдвое сильнее влажного тёплого. Для
слушателя это слабый, но настоящий **относительный** ориентир: Little, Mershon
& Cox (1992) показали, что сигнал с меньшим количеством верхов кажется дальше,
но только в сравнении с похожим сигналом, а не сам по себе.

### 17.3. Влияние земли — ISO 9613-2:1996

Второй спектральный эффект, который обычно забывают, а для шагов он главный,
потому что источник лежит на самой земле. Прямая волна и волна, отражённая от
грунта, складываются; над **пористым** грунтом (трава, снег, песок, листва)
отражение идёт с поворотом фазы, и в полосе **250…1000 Гц** возникает провал,
растущий с расстоянием (Embleton 1996: провал 200…1000 Гц, до 20–30 дБ на
сотнях метров). Над **твёрдым** (бетон, асфальт, металл, вода) отражение
складывается в фазе: +3 дБ по всему спектру (ISO даёт −3 дБ затухания при G = 0).

ISO 9613-2, общий метод (табл. 3): затухание A_gr = A_s + A_r + A_m, где
зона источника и зона слушателя считаются по высоте h и расстоянию dp:

```
a' = 1.5 + 3.0·e^(−0.12(h−5)²)·(1−e^(−dp/50)) + 5.7·e^(−0.09h²)·(1−e^(−2.8·10⁻⁶·dp²))   125 Гц
b' = 1.5 + 8.6·e^(−0.09h²)·(1−e^(−dp/50))                                               250 Гц
c' = 1.5 + 14.0·e^(−0.46h²)·(1−e^(−dp/50))                                              500 Гц
d' = 1.5 + 5.0·e^(−0.9h²)·(1−e^(−dp/50))                                                1 кГц
63 Гц: −1.5;  125…1000: −1.5 + G·(a'…d');  2…8 кГц: −1.5·(1−G);  средняя зона: −3q(1−G)
```

G — пористость грунта (0 твёрдый, 1 пористый). Для шага: источник hs = 0.05 м,
слушатель hr = 1.6 м. Результат нашего кода, G = 1 (трава):

| d | 63 | 125 | 250 | 500 | 1k | 2k+ |
|---|---|---|---|---|---|---|
| 10 м | +3.0 | −0.2 | −2.8 | −3.3 | −1.0 | 0 |
| 30 м | +3.0 | −0.4 | −7.0 | −8.3 | −2.5 | 0 |
| 100 м | +3.0 | −1.1 | −13.3 | −15.8 | −4.7 | 0 |

То есть шаги по траве в 30 м — это не «меньше верхов», а **дыра в 250…500 Гц**
на 7–8 дБ при почти нетронутых верхах; верха начинает есть воздух только дальше.
По бетону на той же дистанции — ровный спектр на 3 дБ громче. Грунт тулза
ставит сама по выбранной поверхности (бетон/металл/паркет 0, доски 0.1, гравий
0.5–0.6, песок/снег/листва 1), ползунком можно поправить.

### 17.4. Что ещё есть в литературе, но не вошло

- **Ближнее поле < 1 м** (Brungart & Rabinowitz 1999): рядом с головой растёт
  межушная разница на низких частотах, ближний источник «басовитее». У нас
  шаги ближе 1 м не бывают; при 1 м кривая ровная.
- **Реверберация / прямой-к-отражённому** — самый сильный ориентир дистанции в
  помещении (Zahorik 2002), по условию задачи не трогаем; это будущая «Комната».
- **Рефракция ветром и температурой, турбулентность** — меняют уровень на сотнях
  метров и делают его плавающим; для игры лишнее.
- **Доплер** — только для движущихся источников.

## 18. Как сделано в тулзе (`distance.js`)

1. Из трёх членов собирается одна кривая |H(f)| в дБ относительно 1 м:
   `−α(f)·(d−1) − A_gr(f, d, hs, hr, G)`; расхождение `−20·log10(d)` идёт в
   отдельный GainNode (плавно, setTargetAtTime).
2. Кривая на сетке 4096 точек → вещественный кепстр → **минимально-фазовый FIR**
   1024 отсчёта (ConvolverNode, normalize off). Минимальная фаза нужна, чтобы у
   транзиента пятки не было пре-эха; пик импульса на отсчёте 1.
3. При смене параметров строится новый свёртыватель и за 15 мс кроссфейдом
   подменяет старый (не щёлкает при перетаскивании; пересчёт не чаще раза в 60 мс).
4. Проверка в браузере: белый шум через узел → октавы совпадают с расчётной
   кривой с точностью 0.1 дБ (125 Гц…8 кГц).
5. UI: главный ползунок «Дистанция» в метрах (1…200 м, лог), под ним картинка
   кривой (сплошная — всё вместе, пунктир — только воздух и расхождение);
   подползунки Температура (−20…+40 °C), Влажность (10…100 %), Грунт (0…1), пресеты
   воздуха (лето, жара, зима, сырость, сухо). Та же шина стоит у эмбиента (ветер:
   грунт выключен, он не на земле).
6. Экспорт WAV (часть 3) сможет печь дистанцию в файл тем же FIR, или оставлять
   «сухой» 1 м и отдавать кривую игре как таблицу RTPC по октавам (`Distance.table`).

# Часть 5. UVI Whoosh FX: как устроен и наш модуль вжухов (01.11.2026)

## 19. Из чего состоит Whoosh FX (по официальному мануалу, v1.0)

Это саундбанк для UVI Workstation / Falcon, 2.5 ГБ: 401 пресет, 545 сэмплов
(96 кГц → 48 кГц). Сами сэмплы лежат в зашифрованном `.ufs`, по файлам их не
посмотреть; разбор по мануалу и картинкам интерфейса.

**Три источника.** Noise (синтез: Band, S+H, Violet, Blue, White, Pink, Brown,
Lorenz, Rossler, Logistic, Sinus) и Texture 1 / Texture 2 (полевые записи и синтез,
15 категорий: Air, Distorted, Electricity, Fire, Fx, Material, Metal, Motor, Noise,
Orchestral, Rock, Sparkle, Synth, Water, Wind; питч ±24 полутона, Randomize/Undo).
У каждого слоя: громкость, Mute/Solo, панорама, Tilt (наклон спектра), Width
(только у шума), фильтр LP / Comb / HP со своим срезом, Link срезов.

**Огибающие в центре.** Три цветные кривые (одна на слой), рисуются мышью или
берутся из пресетов; Time/Amplitude Nudge (сдвиг влево/вправо, плюс/минус), Smooth,
L/R lock (держать левый или правый край), Curve, кнопка All — рисуешь одну
форму на все три и дальше разводишь по времени и громкости. Огибающая ведёт и
громкость, и фильтр слоя. **Warp** над редактором тянет все огибающие влево или
вправо разом.

**Время и движение.** Duration в секундах или долях такта, до 32 с / 8 тактов,
Loop и Ratio; Parameter Lock, чтобы длительность не сбивалась при смене
пресета. Блок Movement: Image Mode (Mono / Stereo / Wide), **Pass-By**
(направление движения), **Speed Curve** (как меняется скорость), **Mode** (Doppler
или одна из трёх огибающих как кривая питча), **Pitch** (глубина питча, %).
LFO Amplitude: вкл, Frequency, Depth, Shift (частота уходит вверх/вниз за
время звука — это статтеры и райзеры). Глобальный фильтр: Depth, Resonance,
Tone, Velocity + Velocity Curve; Key Tracking.

**Вкладки.** Sources (всё выше), Vowel (морфинг-фильтр гласных: верхняя и нижняя
гласная, огибающая перехода, Copy Env, Formant, Q), FX (Convolver, 5-полосный EQ,
Delay с Rotate, IR Reverb, Limiter).

**Пресеты по типам:** Classic / Epic / Flange / Sub, Cinematic, Elements (Fire,
Rocks, Water, Wind), Motion (Fly-By, Foley: Clothes Hit, Cape, Hammer, Sword;
Swish; Swoosh), UI, Pass-By (Engine, Helico, Plane, Spaceship, Train), Rises,
Drops, Fx (Ambiences, Loops, Misc). То есть один и тот же движок кроет и
взмах плаща, и пролёт вертолёта, и подъём к удару в трейлере.

**Что в нём главное, если пересказать одной фразой:** вжух = несколько шумовых
или текстурных слоёв, у каждого своя нарисованная огибающая громкости, которая
заодно двигает фильтр, плюс движение (панорама и Доплер) поверх всего и
общая длительность. Всё остальное — украшения.

## 20. Наш модуль «Вжухи» (`whoosh.js`)

Повторяет ядро и добавляет физику движения, которой в Whoosh FX нет (там
Pass-By и Speed Curve — абстрактные кривые).

| Что | Whoosh FX | У нас |
|---|---|---|
| Слои | Noise + Texture 1 + Texture 2 | то же: шум (белый, розовый, коричневый, голубой, фиолетовый, полоса, S+H, синус) + две текстуры wav (любой файл кнопкой, по умолчанию наш ветер) |
| На слой | Vol, Pan, Tilt, Pitch, фильтр LP/Comb/HP + срез | громкость, M/S, пан, наклон ±12 дБ, питч ±24 st, фильтр LP/HP/BP + срез |
| Огибающая | рисуется, пресеты, Smooth, All, Warp | рисуется мышью (64 точки), 9 пресетов (волна, мимо, удар, взмах, подъём, спад, обратный, ровно, пульсы), «~» сгладить, «всем», Перекос |
| Фильтр от огибающей | Depth, Resonance, Tone | Глубина (октавы), Резонанс, Тон — срез слоя ходит по огибающей |
| Движение | Image Mode, Pass-By, Speed Curve, Doppler, Pitch | **физика пролёта**: скорость (км/ч), ближняя дистанция (м), направление; из них Доплер `c/(c+v_r)`, громкость `1/d`, панорама по углу; ручка Доплер 0…2× физики; Ширина |
| LFO | Frequency, Depth, Shift | Дрожание: скорость, глубина, разгон |
| Длительность | 0…32 с, sync, loop | 0.2…32 с (лог) |
| Дистанция | нет | блок «Дистанция» из части 4 на всю шину |
| FX | Convolver, EQ, Delay, Reverb, Limiter | пока нет (комната — отдельная задача) |
| Vowel | есть | нет (редко нужно для фоли) |

Как играет: кнопка «Вжух» или клавиша W; на каждый слой создаются свежие
узлы, все кривые (громкость × пролёт × LFO, срез фильтра, скорость
воспроизведения с Доплером, панорама) считаются заранее на 256 точек и
ставятся через `setValueCurveAtTime` — ничего не щёлкает, результат
воспроизводим. «Стоп» / X гасит. Шесть характеров: взмах, плащ, машина мимо,
порыв ветра, подъём, стрела.

Проверено в браузере: машина 60 км/ч в 3.8 м → Доплер 1.7 полутона от
приближения до удаления (как по формуле), громкость от −20 дБ по краям до
0 в ближней точке, панорама −1 → +1, на мастере горб в середине события.

## 21. Что из Whoosh FX взять эмбиенту и шагам

**Эмбиенту:**
1. **Порывы** — слой ветра с огибающей-«волной» поверх петли: кнопка или
   маркер на таймлайне даёт порыв заданной длины и силы; срез фильтра
   ходит по огибающей (в Whoosh FX это «WIND Gust»). Готово в движке вжухов,
   остаётся кнопка «порыв» в наборе эмбиента, запускающая вжух с текстурой
   ветра.
2. **Дрожание** (LFO с разгоном) для флаттера листвы и дребезга.
3. **Наклон (Tilt)** на слой вместо только среза: одной ручкой «темнее ↔ ярче».
4. **Пролёт** для машин, птиц, дронов под видео: скорость + дистанция + направление.

**Шагам:**
1. **Взмах ткани на шаг**: короткий вжух (плащ, штанина) на каждый шаг с
   огибающей «взмах», громкость от веса и темпа — это слой «одежда» из Walker,
   но синтетический, без библиотеки.
2. **Персонаж проходит мимо**: та же физика пролёта на всю шину шагов
   (панорама и 1/d по времени), когда герой пересекает кадр; задаётся
   скоростью из темпа и шириной кадра.
3. **Огибающая на удар**: рисуемая форма атаки/спада для пятки и носка (вместо
   фиксированной атаки), это и есть «Attack/Decay» из полос Walker.
4. **Доплер для пробегающего** — заметен только при скорости > 20 км/ч, так
   что для бега почти ноль; честно говорить, что это не слышно.

Источники: UVI Whoosh FX Soundbank Manual v1.0 (uvi.net, 14 стр.); страница
продукта uvi.net/whoosh-fx; обзоры rekkerd.org и epicomposer.com.

# Часть 6. Экран-схема и слои удара (01.11.2026)

## 22. Экран-схема (`graph.js`)

Второй режим центра (кнопка «видео / схема» над кадром, клавиша V). Видео
уходит в слот над центральным узлом и продолжает играть. По референсу владельца
(«your brand» с карточками слева и справа на светящихся линиях):

- **Узел в центре** — название набора и его выбор (ботинки · бетон), кольцо
  дышит от уровня мастера, вспыхивает при каждом ударе.
- **Карточки компонентов** слева и справа: иконка, имя, строка-сводка
  (какие полосы включены), громкость, метр уровня. Линия от карточки к узлу
  светится цветом набора (шаги янтарные, вжухи фиолетовые, эмбиент бирюзовый),
  при ударе по линии пробегает импульс и карточка вспыхивает.
- **Карточка раскрывается в слои**: у шагов это четыре полосы удара (низ,
  середина, верх, атака) с громкостью, питчем и спадом; у вжухов — фильтр,
  питч, пан, наклон и рисуемая огибающая; у петель — громкость и файл.
  Те же блоки, что в левой панели, один код (`Steps.renderBands`,
  `Whoosh.renderLayerControls`).
- **Плитки сверху**: шагов сыграно, голосов, шагов/мин, дистанция, сэмплов в
  памяти (у вжухов: вжухов, длительность, скорость, ближняя дистанция, доплер).
- Клик по иконке карточки глушит компонент (как M в списке слоёв).

## 23. Слои удара (`steps.js`, BANDS)

Каждый удар (пятка, носок, отрыв, скольжение, лестница, доп. поверхность,
аксессуары) играется не одним голосом, а четырьмя полосами одного сэмпла:

| Полоса | Что | Как |
|---|---|---|
| низ | < 220 Гц | Линквиц-Райли 4-го порядка (два Баттерворта Q = 0.707) |
| середина | 220 Гц … 2.5 кГц | HP LR4 + LP LR4 |
| верх | > 2.5 кГц | HP LR4 |
| атака | полный спектр, первые 2…60 мс | окно, спад 3 мс |

У каждой полосы включатель, громкость −24…+12 дБ, питч ±12 полутонов, спад
5 мс…2 с («как есть» = огибающая записи). При нулевых настройках три полосы
складываются ровно в исходный сэмпл (LR4 суммируется плоско и в фазе), так
что разбиение ничего не красит, пока не крутишь. Атака по умолчанию −9 дБ,
чтобы не удваивать транзиент. Настройки полос сохраняются в проект.

Один шаг по бетону в ботинках с двумя аксессуарами = 9 ударов × 4 полосы =
36 голосов; для Web Audio это дёшево.

## 24. Дизайн

Шрифт Inter, иконки — свой SVG-спрайт в стиле Lucide (`#i-*` в index.html),
цвет на тип набора, вкладки-таблетки, карточки, чип значения у ползунка,
кастомные выпадающие списки. Референсы владельца (01.11): тёмные «железки» с
крутилками и подсвеченными окошками значений (Bassmaker), ползунок со

## 25. Крутилки и тумблеры (`knob.js`)

Крутилка живёт поверх обычного `<input type="range">`: сам input остаётся в
DOM скрытым, все обработчики работают как раньше, крутилка меняет его
значение и шлёт событие `input`; обратное направление (код сам ставит
`input.value`) ловится переопределённым сеттером. Поэтому одной функцией
`Knob.convert(root)` в крутилки превращены все ползунки: главные макросы
(большие, янтарные), подползунки (мини, зелёные), полосы удара и слои вжухов
(мини). Фейдеры громкости слоёв и скраббер оставлены ползунками (`data-fader`).

Управление: тянуть вверх/вниз (весь диапазон за 300 px), Shift — в 10 раз
точнее, колесо — по шагу, двойной клик — сброс в дефолт. Вид по референсу
Bassmaker: тёмное тело с градиентом, дуга и указатель цветом набора со
свечением, окошко значения под ручкой с внутренней подсветкой; у биполярных
диапазонов (питч, наклон) дуга идёт от нуля. Чекбоксы (полосы, слои вжухов)
стали стеклянными тумблерами со свечением.

# Часть 7. Экспорт шага WAV-файлами слоями (01.11.2026)

## 26. Как устроено (`export.js`)

1. **План шага.** Удар больше не играется «на лету»: сначала строится план
   (`Steps.planStep`): какой сэмпл у каждого компонента (round-robin без
   повторов, зона силы), случайный питч, громкость и сдвиг на каждый удар,
   будет ли скольжение. Вживую план сразу проигрывается (`Steps.playHit`),
   при экспорте — рендерится.
2. **Сеяная случайность.** На время экспорта `Math.random` подменяется
   генератором с зерном (mulberry32), зерно = «зерно × 7919 + вариант × 104729».
   Один и тот же рецепт даёт байт в байт те же файлы (проверено: повтор
   отличается на 8·10⁻⁶, это шум float в свёртке полос).
3. **Группы.** Компоненты раскладываются по группам в окне экспорта
   (по умолчанию: шаг = пятка+носок+отрыв, ткань = аксессуары, поверхность =
   доп. поверхность + скольжение; любой компонент можно переложить или
   выключить). Каждая группа рендерится отдельным проходом на
   `OfflineAudioContext` тем же графом, что играет (`Steps.buildBus`: полосы,
   макро-громкости, пользовательские громкости и M/S, low-shelf, фильтры шины;
   дистанция по желанию через `Distance.createStatic`). Сумма файлов
   одного варианта равна файлу микса (проверено: разница 7·10⁻⁶).
4. **Обрезка и уровень.** Хвост режется по −80 dBFS плюс 50 мс. Нормализация:
   своя на группу (к −1 dBFS по самому громкому варианту группы), одна на всё
   (отношения между группами сохраняются, как слышно) или нет.
5. **Файлы.** WAV PCM 24 или 16 бит, 48 / 44.1 / 96 кГц, стерео. Имя
   `<префикс>_<группа>_<nn>.wav`, префикс по умолчанию `FOOT_<обувь>_<поверхность>`.
   Всё пакуется в zip (без сжатия, свой упаковщик) вместе с `recipe.json`.
6. **recipe.json**: выбор обуви/поверхности/слоёв, все значения крутилок,
   полосы, параметры движка, дистанция, настройки экспорта, зерно и для
   каждого файла список ударов: компонент, имя сэмпла, момент в мс, питч в
   центах, громкость в дБ. По нему можно вернуться и перевыгнать.

Окно: кнопка «Выгнать WAV» в шапке или клавиша E; нужно, чтобы сэмплы шагов
были загружены. Шесть вариантов × три группы + микс = 24 файла за доли секунды.

Не сделано: экспорт вжухов и эмбиента тем же путём (движок вжухов уже
считает кривые заранее, остаётся обернуть), YAML под SFX Audio System для
Unity, стем под весь ролик по маркерам.

## 27. Жёсткость в центре схемы, живые крутилки, значок (01.11.2026)

- **Жёсткость** — новый макрос у шагов и вжухов (`hub: true`), сидит в
  центральном круге схемы и как крутилка справа. Тянуть круг вверх/вниз,
  колесо, двойной клик — сброс. У шагов: сдвигает зону силы (мягко 01-59 ↔
  жёстко 110-127), атаку ±9 дБ, верх на шине ±5 дБ (high-shelf 3 кГц). У
  вжухов: резонанс фильтра и верх ±5 дБ. Цвет кольца: бирюзовый (мягко, ASMR)
  → янтарный → красно-оранжевый (очень жёстко), свечение растёт с жёсткостью.
- **Крутилки при вращении**: риски по дуге, блик и точка на ручке вращаются
  вместе с указателем, во время тяги или колеса над ручкой всплывает крупное
  окно со значением (то, что написано в подписи: метры, °C, дБ).
- Иконки на карточках схемы и в плитках уменьшены (28 px вместо 38), крутилки
  58/36 px вместо 66/40.
- **Значок приложения**: `layerlab/tools/make_icon.py` (Pillow) рисует
  `layerlab/desktop/icon.png` и `icon.ico` (тёмный скруглённый квадрат, янтарное
  кольцо со свечением, три слоя: фиолетовый, зелёный, янтарный). Значок стоит
  на ярлыке рабочего стола и в окне Electron.

# Часть 8. Цепочка модулей, правки по слуху владельца (01.11.2026)

## 28. Цепочка обработки (`fx.js`)

Между компонентами набора и дистанцией стоит цепочка модулей, одна на набор
(шаги, вжухи, эмбиент), и та же цепочка строится при экспорте. Каждый модуль
включается тумблером (кроссфейд сухого и обработанного), у каждого свои
ручки 0…100:

| Модуль | Что делает | Ручки |
|---|---|---|
| Мягкость | lowpass + полка от 4 кГц: тупее, ближе к ASMR | срез 800 Гц…20 кГц, верх −18…0 дБ |
| Сатурация | WaveShaper tanh, 2× оверсэмплинг | драйв, микс |
| Компрессор | DynamicsCompressor, можно придавить атаку | порог, степень, атака, отпуск, добавка |
| Эквалайзер | полки 120 Гц / 1 кГц (пик) / 6 кГц | низ, середина, верх ±12 дБ |
| Комната | свёртка с синтетическим затухающим шумом | размер 0.05…0.8 с, микс 0…50 % |

Справа секция «Цепочка» с карточками модулей; под кругом схемы чипы,
клик по чипу включает модуль. Настройки лежат в `set.fx` и сохраняются в
проект.

## 29. Правки по слуху

- **Пауза пятка → носок** была 139 мс при среднем темпе, стала 94 мс
  (диапазон 150→25 мс; у BOOM по умолчанию 75). Носок → отрыв 128 мс
  (200→40). Скольжение стартует через 10 мс после носка, а не 30.
- **Дистанция** звучала как «просто тише»: честные −6 дБ на удвоение на
  200 м давали −46 дБ, а воздух по ISO на 30 м режет 8 кГц всего на 3 дБ.

  усиливается на треть от этого). На 50 м по умолчанию: −17 дБ и −11 дБ на
  8 кГц, слышно и спектр, и расстояние.
- **Бегущие полосы** на линиях при ударе убраны, осталась вспышка.
- **Цифры тянутся**: любая подпись-значение (громкость карточки, окошки под
  крутилками, подписи полос) — зажал и тянешь вверх/вниз, колесо, двойной

- **Контур вокруг круга** показывает жёсткость: пусто при 0, половина при

## Часть 9. Модули на ниточках и «Умный EQ» (2026-11-01)

**Цепочки.** Обработка теперь не фиксированный набор флагов на шине, а два вида упорядоченных списков экземпляров
`{ uid, id, on, p }`: на каждой ниточке «компонент → узел» (`set.wireFx[compId]`) и на шине набора «узел → дистанция»
(`set.fx`). Один модуль можно поставить несколько раз, порядок = порядок по ходу сигнала. На схеме над телом —
палитра плиток (`.g-palette`); плитку тянут на ниточку (блок появляется на линии, равномерно по длине) или на узел
(ряд «шина» под кругом). Блок: клик — всплывашка с ручками, перетаскивание — на другую ниточку или в пустоту (убрать).
Та же цепочка строится при экспорте (`Fx.build(ctx, list)` без ключа), поэтому WAV звучит как в тулзе. Старые проекты
с `fx: [{id, on, p}×5]` мигрируют: остаются только включённые модули (`Fx.migrate`).

**Умный EQ (`aeq`)** — один модуль, два режима-опции, можно оба:
* *По слуху* — ISO 226:2003 (кривые равной громкости, в быту «Флетчер–Мансон»). Модуль меряет RMS сигнала,
  переводит в фоны через калибровку «0 dBFS = N дБ SPL» (по умолчанию 90) и ставит 10 октавных фильтров
  (31,5 Гц … 16 кГц) на поправку `g(f) = [Lp(f, L) − Lp(f, Lref)] − (L − Lref)`, где `Lp(f, фон)` — контур ISO,
  `L` — текущая громкость в фонах, `Lref` — «опора» (по умолчанию 85 фон, как слышалось бы вблизи).
  Тихий сигнал (L < Lref) ⇒ ухо теряет низ и верх ⇒ докручиваем их; громче опоры ⇒ наоборот. Проверка формулы:
  40 фон → 1 кГц 40,0 дБ; 100 Гц 64,4 дБ; 20 Гц 99,9 дБ (совпадает с таблицей стандарта). Громкость следит вверх
  сразу, вниз 10 дБ/с, в тишине ничего не меняется (чтобы атака шага не выезжала с лишним низом).
  Это именно зависимость от громкости сигнала, не от дистанции: дистанция отдельно (distance.js).
* *К шуму* — долгий спектр сигнала по тем же октавам (FFT 4096) сравнивается с целевым наклоном: белый 0 дБ/окт,
  розовый −3, коричневый −6; отклонение (минус среднее) гасится на «силу» %, со временем слежения «скорость».
При экспорте (офлайн нет анализатора) берутся последние живые усиления полос этого экземпляра (`Fx.memo(uid)`),
если модуль ещё не слышал сигнала — считается −20 dBFS.


## Часть 10. Понятные модули, звук только у открытой вкладки, поверхности плитками (2026-11-01, вечер)

Замечания владельца после части 9: «выглядит по-аишному», круг некрасивый, названия модулей непонятны, непонятно,
куда вешать модуль и что такое «шина», не видно, что модуль сделал; эмбиент приходится ходить выключать;
поверхности хочется картинками с вариациями-пресетами.

**Модули.** «Мягкость» убрана (её делали срез и полка, то же даёт эквалайзер). Осталось пять: Сатурация, Компрессор,
Эквалайзер, Умный EQ, Комната. У каждого значок (спрайт `#i-sat/#i-comp/#i-eq/#i-ear/#i-room`), а в `Fx.MODULES`
кроме `hint` — `desc` (что делает) и `hear` (что слышно). Подсказка при наведении (`ui.js`, `Tip`): любой элемент с
`data-tip` показывает всплывашку через 350 мс; текст собирает `Tip.html(название, что делает, что слышно)`.
Палитра над схемой — плитки «значок + название + коротко», блоки на ниточках — только значок.

**Куда вешать.** Слово «шина» ушло. Ряд под кругом подписан «весь набор», в подсказке: сюда попадают все слои уже
смешанными, перед дистанцией; модуль на ниточке действует только на свой слой. Призрак при перетаскивании пишет,
куда ляжет модуль: «Умный EQ → только «пятка»» / «→ на всём наборе» / «убрать». Во всплывашке модуля первая строка —
где он стоит и что это значит. В правой панели раздел переименован в «Модули на всём наборе».

**Что модуль делает — видно.** `FxView.mount(box, cfg, key)` рисует живую картинку в каждой карточке модуля
(всплывашка на схеме и правая панель): эквалайзер и умный EQ — кривая тембра 20 Гц…20 кГц ±18 дБ, считается из
`BiquadFilterNode.getFrequencyResponse` живых фильтров (у умного EQ она ездит вместе с громкостью сигнала);
компрессор — кривая вход→выход с точкой текущего уровня и столбик «на сколько дБ сейчас прижимает»
(`DynamicsCompressorNode.reduction`); сатурация — кривая насыщения с точками текущего пика; комната — сухой удар
и хвост. Под картинкой два метра «вход / выход» (анализаторы `anIn`/`anOut` в каждом живом модуле) и строка-пояснение
(«−27 dBFS → 63 фон · низ +6,6 дБ · верх +2,8 дБ», «прижимает на 1,8 дБ», «ниже порога — не трогает»). Пока звук не
запущен, кривая берётся с тихой копии модуля на OfflineAudioContext (`Fx.preview`), чтобы ручки сразу было видно.

**Звук только у открытой вкладки.** Каждый набор выходит в мастер через свой gain (`setOutput(setId)` в app.js, им же
пользуются шины шагов и вжухов). При смене вкладки `applyFocus()` даёт 1 текущему набору и 0 остальным (плавно, 50 мс).
Тумблер «слышать все наборы» под вкладками включает всё сразу (запоминается).

**Поверхности и обувь плитками.** В панели шагов вместо двух списков — плитки: обувь со значками (`#i-shoe-*`), поверхности
с фактурами `img/surf/*.png` (320×200, считаются `tools/make_surfaces.py` из шума и фигур numpy — бетон, крошка, гравий
двух размеров, металл, песок, паркет, доски; не картинки из нейросети). Под поверхностью — ряд вариаций: встроенные
«мягко / ровно / мощно» (жёсткость, вес, шарканье) и свои: «+ сохранить» запоминает всё как сейчас (ползунки, выбор
обуви и слоёв, полосы, модули на ниточках и на наборе) под именем для этой поверхности; × убирает. Хранятся в
`set.vars[поверхность]` (попадают в json проекта) и дублируются в localStorage, чтобы пережить F5 без сохранения проекта.
В библиотеке BOOM VFA нет травы и снега — плитки только для её восьми поверхностей; свои поверхности появятся вместе
со своими звуками владельца.

**Меньше неона.** Круг — тёмный диск-ручка с указателем и дугой значения на 270° (без свечения), подпись
«обувь · поверхность» под диском. Убраны тени-свечения у крутилок, блоков, метров, тумблеров, логотипа.


## Часть 11. Психокружочек, погода, темп, дуги выбора, трава (2026-11-01, ночь)

Владелец показал четыре картинки-референса: круг из долек (trove), ручку с ребристым кольцом и внешним кольцом
(«60 percent»), веер с погодой и дуговой выбор жанра. Всё это собрано в один экран-схему.

**Круг из долек (`graph.js`).** Долька = слой набора, длина дольки = громкость слоя (0…100 → от внутреннего радиуса
до края). Тянуть дольку вверх/вниз — громкость, Ctrl+клик — выключить/включить (мьют, пунктирный контур), клик —
подробности слоя (полосы удара / огибающие вжуха), колесо — по шагу, двойной клик — 80. Светлость дольки растёт с
громкостью, удар подсвечивает дольку цветом набора и гаснет, уровень слоя — полупрозрачная заливка. У шагов рисуются
только компоненты, у которых есть сэмплы (пустые слоты вроде «доп. поверхность: нет» не занимают места).

**Центр.** Ребристое кольцо (72 засечки) — «Жёсткость»: крутишь вокруг центра, кольцо вращается вместе со значением
(270° на 0…100), число посередине, под ним слово (мягко · ASMR … очень жёстко), цвет засечек от бирюзового к красному.
Между кольцом и дольками — кольцо из восьми сегментов: модули на всём наборе (бывшая «шина»). Плитку из палитры
бросаешь на сегмент (порядок по кругу = порядок обработки), по сегменту тянешь влево/вправо — микс этого модуля
(сухой ↔ обработанный, теперь есть у всех пяти), клик — ручки и живая картинка. Владелец хочет сюда VST-плагины:
в браузерном движке (Web Audio внутри Electron) чужие VST не загрузить без нативного моста; кольцо держит наши модули,
список внешних плагинов обсудим, когда он назовёт, какие.

**Веера (`dial`-макросы).** Веер 150° крутится под неподвижной стрелкой; значение 0…100 непрерывное, подсветка
сектора и подпись говорят, к какому состоянию ближе. «Темп»: крадётся (10) · идёт (45) · бежит (85) — это прежний
макрос темпа с подползунками, главный тянет их за собой. «Погода»: сухо (0) · сыро (50) · дождь (100), новый макрос
`wet`. Клик по сектору ставит его середину, кнопка внизу — сброс.

**Погода: как это делают профи.** Общий приём в играх — поверхность остаётся «сухой», а вода идёт отдельным слоем с
плавной громкостью от параметра влажности (CRI AtomCraft: water как слой поверх любой поверхности с AISAC-контролем
«wetness»; в Wwise то же через RTPC на громкость слоя, Audiokinetic Q&A по Limbo показывает RTPC-кривые громкости
шагов). Библиотеки для фоли (Tovusound Edward и его outdoor-расширение) вместо ползунка записывают мокрые варианты
поверхностей отдельно: Puddle, Water, Gravel Wet, Snow. BOOM VFA ближе к первому подходу: отдельный слой
Generic Water (пятка/носок/отрыв по зонам силы) и Puddle только как демо-прогулка. Поэтому у нас:
* `water` (BOOM Generic Water) — с «сыро»: −26 дБ при 8 % влажности, 0 дБ при 80 %;
* `puddle` (нарезка демо-лужи, `tools/slice_demo.py`) — с «дождь»: от −20 дБ при 50 % до 0 дБ при 100 %;
* срез поверхности: мокрое звучит глуше — lowpass от 20 кГц до 6 кГц между 25 % и 100 %;
* ливень как фон не синтезируем: это отдельная петля в наборе «эмбиент», когда владелец даст запись дождя.
Оба слоя — обычные компоненты шага (дольки «вода под ногой» и «лужи»), грузятся всегда, попадают в экспорт
(группа «поверхность»). Литература: Turchet, «What do your footsteps sound like? An investigation on interactive
footstep sounds adjustment» (UCL) — люди предпочитают подстраивать шаги непрерывными ручками, а не выбирать из списка;
это и есть веер.

**Дуги выбора (`pickers`).** Слева от круга две дуги: обувь (значки) и поверхность (фактуры). Список едет по дуге
(колесо, перетаскивание), выбранное в середине крупнее, клик — выбрать. Те же выборы остаются плитками в левой панели.

**Трава и снег.** В BOOM VFA PART 1 травы нет: только Leaves, Snow, Water как нарезанные доп. слои. В PART 2 лежат
демо-прогулки по одной на поверхность (53 с, 96 кГц), в том числе Generic Grass и Generic Puddle. `tools/slice_demo.py`
режет их по началам шагов (подъём > 10 дБ за 30 мс, не чаще раза в 200 мс, хвост до тишины или 1,5 с) в
`media/vfa-extra/<Имя>/NN.wav` (48 кГц, 24 бит) и пишет index.json с громкостью куска; движок (`loadFiles`) делит
куски на три зоны силы по RMS. Трава: 81 шаг, лужа: 94 куска. Составные поверхности `COMBOS`: «трава» = песок +
слой травы на 90 %, «снег» = песок + слой снега; выбираются той же плиткой/дугой, `set.select.combo` помнит выбор.
Фактуры плиток травы и снега — тоже процедурные (`tools/make_surfaces.py`).
